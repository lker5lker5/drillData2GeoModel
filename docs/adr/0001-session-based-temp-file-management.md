# ADR-0001: Session-Based Temporary File Management

**状态**：已批准  
**日期**：2026-10-03  

## 背景

项目运行几个月后，`outputs/` 目录积累了大量测试数据（348MB / 410 个文件，最早可追溯到 8 月）。这些文件中大部分是测试过程中生成的图片，用户无法区分哪些是当前有效的、哪些是历史遗留的。系统没有自动清理机制。

## 决策

采用 session 级别的临时文件管理方案：

1. **输出文件按 session 分组**：所有生成结果从 `outputs/` 平铺式根目录改为 `outputs/{session_id}/` 子目录
2. **Session 超时清理**：60 分钟无活动自动清理该 session 的所有数据（outputs + uploads）
3. **上传新文件自动清理旧 session**：同一 tab 内，上传新文件时先清理上一个 session
4. **"新建会话"按钮**：允许用户主动清理并重置
5. **启动时清理遗留数据**：Flask 启动时删除所有非 session 子目录下的历史文件
6. **下载保持现有样式**：不新增批量下载入口，沿用 carousel 现有的"下载当前图"和"下载全部"按钮

## 考量因素

### 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A) 按 session 分组 + 超时清理**（选定） | 清理精确、结构清晰、session 间不干扰 | 需要修改所有后端路由的输出路径 |
| **B) 平铺结构 + 时间戳清理** | 改动最小 | 无法精确匹配文件所属 session，可能误清除活跃文件 |
| **C) 平铺结构 + manifest 追踪** | 不改路径，清理精确 | 仍需要修改所有路由注册 manifest，复杂度接近 A 但不如 A 直观 |

### 风险

- **并发 session**：当前架构为单用户 Flask 应用，无并发问题。如果未来改为多用户，`session_last_active` 字典需要持久化
- **URL 缓存**：前端可能缓存旧的 `/outputs/xxx.png` URL（session ID 路径段变化后，旧 URL 失效，这是预期行为）
- **数据丢失**：用户可能忘记下载重要数据。设计上一开始就以"数据是临时的"为出发点，下载是主动行为

## 影响范围

- `mineDrillApp.py` — 修改所有生成输出文件的路由，新增 session 活跃跟踪和清理逻辑
- `main.js` — 新增"新建会话"按钮 handler
- `index.html` — 新增"新建会话"按钮 DOM
- `config.py` — 新增 `SESSION_TIMEOUT_MINUTES = 60`

## 理由

- 用户明确表示"绝大部分数据都是测试数据"，需要一种低心智负担的管理方式
- Session 级别的隔离使清理精确到会话，不互相干扰
- 超时清理是兜底机制，用户可下载后再关闭页面，不丢失数据
- 启动时清理历史数据一次性解决当前的 348MB 测试数据堆积问题
